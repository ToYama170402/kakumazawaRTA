# セキュリティレビュー（走行履歴暗号化）

## 対象

- 走行単位で生成する暗号鍵
- 端末内に一時保存する位置履歴
- 送信前に必要となる復号フロー

## 実装方針

- 鍵はOSのKeystore/Keychainに保存する。
- 鍵は走行開始時にランダム生成し、走行IDと紐付ける。
- 位置履歴はAES-GCM (256-bit) で暗号化し、ローカルには暗号文のみを保存する。
- 送信直前にのみ復号し、送信後は暗号文と鍵を削除する。

## 脅威と対策

- 端末上ファイルの直接参照
  - 対策: 暗号化済みデータのみ保存する。
- 走行データと鍵の漏えい
  - 対策: 鍵はSecure Storage経由でOS管理領域に保存する。
- 改ざんデータ注入
  - 対策: AES-GCMの認証タグ検証により改ざん検知する。

## 残課題

- 再送キューとの結合時に、復号失敗時のリトライ制御方針を追加する。
- 送信失敗時の鍵保持期間とクリーンアップポリシーを運用要件で確定する。
