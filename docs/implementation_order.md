  計測できる（GPS・境界判定）→ 守れる（暗号化）→ 再送できる →
  画面」の順で、各段が前段の部品を使う。

## 設計書に無いため、このPRで仮置きした判断

1. **階級（rank_grade）の数値基準**が設計書に無い。 →
   `routes.rank_thresholds`（任意・JSON）を追加し、未設定なら
   `rank_grade = null`
   を返すようにした。基準値が決まればデータ投入だけで対応できる。
2. **境界長方形（start_bounds / goal_bounds）のJSON形式**が未定義。 →
   `{"min_lat", "max_lat", "min_lng", "max_lng"}`
   と定義し、DBのCHECK制約で担保した。クライアントの境界判定（段7）もこの形式を使う。
3. **平均速度**の定義が「長時間平均」とのみ書かれている。 → 移動距離の合計 ÷
   全所要時間 とした。始点・終点の直線距離ではない。
